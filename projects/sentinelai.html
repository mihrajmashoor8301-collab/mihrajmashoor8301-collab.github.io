info OVERVIEW & MISSION // 01

What is SentinelAI?

psychology Purpose & Problem Addressed

Vulnerability assessment workflows frequently suffer from fragmented tooling: reconnaissance port scans produce raw text banners, CVE feeds produce overwhelming noise without asset context, and remediation plans require tedious manual synthesis.

The portfolio project documentation describes SentinelAI as an active security engineering platform designed to resolve this fragmentation. Instead of relying on generic public chatbots that leak sensitive infrastructure details, SentinelAI operates strictly on-premises using local neural models to correlate security intelligence and structure findings into actionable roadmaps.

target Intended Audience & Scope

SentinelAI is built for security engineers, vulnerability analysts, and offensive security practitioners conducting authorized technical evaluations on owned or simulated lab systems.

It unifies log parsing, CVE correlation, CVSS scoring, and graph-based threat context while maintaining authorization and approval primitives at every dispatch stage, ensuring multi-step orchestration remains strictly auditable and controlled.

hub KNOWLEDGE GRAPH

Security Knowledge Graph with MITRE ATT&CK mapping across tactic vectors and asset-software relationships.

Contextual exposure analysis engine correlating parsed service banners with CVE records and CVSS severity metrics.

terminal DISPATCH & AUDIT

Step-by-Step Documented Workflow

1 INPUT
Telemetry Ingestion

Reconnaissance scan logs, such as Nmap port scan service banners and asset configuration details, are submitted to the platform.

2 PROCESSING
Graph & CVE Mapping

Parsed banners are correlated against CVE vulnerability intelligence and mapped into the MITRE ATT&CK knowledge graph across tactic vectors.

3 DECISION
Neural Model Triage

Local neural models running via Ollama evaluate contextual exposure and calculate CVSS-aligned risk priorities through the RAG pipeline.

4 ACTION
Authorized Dispatch

Actions trigger authorization and approval primitives before dispatching remediation roadmaps through the FastAPI or CLI interfaces.

5 OUTPUT
Evidence & Audit

Structured evidence records are stored alongside immutable audit logs, providing full traceability for every assessed asset and action.

shield SECURITY DESIGN & BOUNDARIES // 05

Verified Security Controls & Boundaries

As an engineering platform handling sensitive reconnaissance information and vulnerability assessments, SentinelAI embeds foundational defensive controls directly into its architecture.

gavel Authorization Primitives

Autonomous multi-step actions require explicit approval barriers. High-impact operations cannot be executed autonomously without deliberate human verification.

visibility_off Zero Cloud Leakage

By running local neural models through Ollama on local hardware, sensitive vulnerability telemetry, service versions, and network topologies are never transmitted to external cloud endpoints.

history_edu Immutable Audit Logging

All user inputs, model evaluations, and dispatch queries produce verifiable audit trails with timestamps to support compliance and technical post-mortem analysis.

neurology AI ARCHITECTURE & RETRIEVAL // 06

Local AI Inference & RAG Architecture

The portfolio documentation defines SentinelAI's AI tier around local execution using the Ollama runtime. Instead of transmitting infrastructure data across third-party APIs, inference happens locally on private hardware.

RAG Retrieval Pipeline

Indices of MITRE ATT&CK techniques and CVE intelligence allow the system to fetch relevant defensive mitigation patterns on demand, augmenting the model's prompt context with deterministic security references.

Contextual Exposure Scoring

Rather than generic severity scores, the reasoning engine combines CVSS metrics with asset-specific connectivity and software relationships to compute localized, contextual risk rankings.
