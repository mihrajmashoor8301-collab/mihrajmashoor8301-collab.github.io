What is OpenCode Persistent Memory?

psychology The Problem: Context Evaporation

AI-assisted coding environments suffer from context loss across conversation resets and tool restarts. Important architectural decisions, repository quirks, user preferences, and previous bug fixes are forgotten as soon as the active session window terminates.

The portfolio documentation describes OpenCode Persistent Memory as a portable, fully local memory tier engineered specifically to solve this problem for OpenCode. By capturing developer facts and decisions in the background, it enables continuous, contextual AI assistance across multiple coding sessions.

shield Zero Cloud Dependency & Scoping

Unlike hosted AI memory services that store proprietary code context in third-party clouds, this platform operates 100% locally on the developer's machine using local embeddings and SQLite.

Crucially, it implements project scoping, ensuring that memories, architecture decisions, and operational details recorded in one repository never leak or cross-contaminate another project's workspace.

RESILIENT DUAL-ENGINE ARCHITECTURE
SQLite Authoritative Storage → Chroma Semantic Search + Resilient Keyword Fallback Index

Guarantees that memory retrieval remains continuously available: if the vector embedding service or Chroma daemon encounters an error, the system transparently falls back to SQLite keyword retrieval without breaking the developer's workflow.

route WORKFLOW & RETRIEVAL LIFECYCLE // 03

Step-by-Step Documented Workflow

1 INPUT
Session Interaction

Developer converses with OpenCode, making code changes, architectural decisions, and configuration choices.

2 PROCESSING
Background Extraction

Asynchronous background workers scan the session transcript, extracting durable knowledge and tagging it by project scope.

3 DECISION
Dual-Engine Indexing

Facts are committed authoritatively to SQLite, while local embeddings are generated via Ollama and stored in Chroma.

4 ACTION
Query & Fallback

On subsequent questions, semantic vector search finds relevant context; if Chroma is unavailable, keyword search immediately activates.

5 OUTPUT
Context Injection

Relevant historical facts and architectural choices are injected into the active prompt window, maintaining long-term memory.

code IMPLEMENTATION DETAILS // 04

Technologies & Implementation Architecture

storage SQLite Authoritative Storage

Engineered around an authoritative SQLite database. By storing memory items as ACID-compliant relational rows first, the system avoids vector store corruption and provides instant keyword retrieval capabilities.

Storage: SQLite 3, Relational Schema, Full-Text Indexing
travel_explore Chroma Vector Engine & Ollama Embeddings

Uses Chroma for vector indexing and nearest-neighbor search. Dense vector representations are computed locally through Ollama embedding endpoints, ensuring zero network egress.

Embeddings: Chroma Vector DB, Local Ollama Embedding Model
javascript TypeScript Plugin & Tool Components

Lightweight TypeScript client components integrate directly into the OpenCode environment, exposing tool calling interfaces (`store_memory`, `query_memory`) and managing workspace scoping.

Frontend/Plugin: TypeScript, OpenCode SDK / Tool APIs
package_2 Portable Packaging & Lifecycle Scripts

Includes automated installer and uninstaller shell scripts that configure Python virtual environments, initialize the SQLite schema, and register the OpenCode plugin seamlessly.

Packaging: Portable Shell Installer & Uninstaller

Data Isolation & Privacy Design

folder_shared Strict Project Scoping

Every memory entry is tagged with a hashed workspace root identifier. Memories from private client projects never bleed into open-source or personal workspaces.

wifi_off Zero Cloud Leakage

All vectors, relational tables, and embedding operations stay on local storage. No developer tokens, secrets, or source snippets are transmitted to external services.

delete_sweep Clean Uninstall Routine

Provided uninstaller cleanly purges hooks and local stores without leaving orphaned background services or lingering background tasks.

neurology RETRIEVAL ARCHITECTURE // 06

Dual-Engine Retrieval Pipeline

The core innovation of the retrieval system is its resilience against vector database failures:

Semantic Embedding Retrieval (Chroma)

When the Ollama embedding service and Chroma engine are running normally, semantic vector similarity ranks memories based on conceptual relevance, matching queries even when wording differs.

Keyword Fallback Resilience

If local embedding generation fails or the vector collection is unreachable, queries seamlessly fall back to SQLite keyword matching. The developer receives relevant context without broken execution.
