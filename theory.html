LEVEL 01 // FOUNDATION

Computer Fundamentals & Hardware Abstractions

CORE ARCHITECTURE

A computer is a general-purpose electronic machine capable of accepting input, storing instructions and data, executing logical and arithmetic operations at immense speeds, and outputting meaningful results (Von Neumann Architecture). In cybersecurity, hardware boundaries determine memory safety, instruction execution privileges, and physical isolation guarantees.

memory CPU (Central Processing Unit)

The computational engine executing instructions via the Fetch-Decode-Execute cycle. Contains the ALU (Arithmetic Logic Unit), Control Unit, and high-speed hardware Registers (e.g., RIP instruction pointer, RSP stack pointer).

Security: Spectre/Meltdown exploit CPU speculative execution and branch prediction caches.
developer_board RAM (Random Access Memory)

Volatile high-speed working storage directly addressable by the CPU. Every running program, decrypted secret, and live network socket resides in RAM.

Security: RAM dumping & memory forensics extract unencrypted plaintext credentials and malware payloads.
hard_drive Non-Volatile Storage (SSD / NVMe / HDD)

Persistent block storage holding filesystems, operating system binaries, database tables, and configuration files across power cycles.

Security: Full-disk encryption (LUKS / BitLocker) protects persistent storage at rest from physical theft.
hub Motherboard & System Buses

The circuit board connecting all components via high-speed buses (PCIe, SATA, USB). Houses the BIOS/UEFI firmware that initializes the hardware.

Security: UEFI Secure Boot verifies cryptographically signed bootloader signatures against tampering.
compare_arrows CORE ABSTRACTION: PROCESSES VS THREADS
What is a Process?
🟢 Simple: "A process is a running instance of a program."

Technical Definition: An isolated operating system execution context allocated its own private virtual memory space (Text, Data, BSS, Heap, Stack), a distinct Process Identifier (PID), environment variables, security context/credentials (UID/GID), and an open File Descriptor table. Processes cannot read or write to another process's memory without explicit IPC or debugging privileges.

What is a Thread?
🔵 Simple: "A worker inside a process that executes instructions."

Technical Definition: The smallest schedulable unit of CPU execution. Multiple threads within the same process share the process's address space, code segment, and heap memory, but maintain independent thread execution contexts (registers, program counter, and private stack frame). Concurrency errors like race conditions emerge when multiple threads modify shared variables without synchronization locks.

LEVEL 02 // SYSTEM INTERNALS

Operating System Theory & Kernel Architecture

PRIVILEGE BOUNDARIES

An operating system (OS) is the software layer mediating between physical hardware and application software. It manages hardware resources, enforces access control boundaries, abstracts devices via drivers, and schedules concurrent workloads.

shield CPU EXECUTION RINGS & THE SYSTEM CALL GATEWAY
USER SPACE (Ring 3) — Untrusted Applications & Utilities
Web Browser, Python Scripts, Bash Shell, Nmap, Web Servers (Nginx)
• Cannot access physical hardware directly • Restricted memory access
↓ SYSTEM CALL BOUNDARY (int 0x80 / syscall instruction) ↑
KERNEL SPACE (Ring 0) — Privileged Supervisor Mode
Process Scheduler, Virtual Memory Manager, Hardware Drivers, TCP/IP Stack, VFS
• Full unrestricted hardware control • Kernel panic if crash occurs
Virtual Memory & Paging

The OS presents each process with the illusion of a continuous, private address space. Physical memory is divided into fixed-size Pages (usually 4KB). The MMU (Memory Management Unit) translates virtual addresses to physical RAM addresses via Page Tables.

Process Memory Layout (Stack vs Heap)

Stack: Fast, contiguous LIFO memory storing function call frames, local variables, and return addresses. Grows downward.
Heap: Dynamic memory allocated at runtime via malloc() / new. Grows upward.

Virtual Filesystem (VFS) & Inodes

In Linux, "Everything is a file". An Inode is a data structure storing file metadata (permissions, UID, size, timestamp, data block pointers) — but NOT the filename. Filenames are directory entries pointing to inode numbers.

Environment Variables & PATH Traversal

Key-value pairs inherited by child processes. The PATH variable defines directories searched for executable binaries. Misconfigured paths (e.g., writable directory listed first) allow binary hijacking and privilege escalation.

security_update_warning HOW OS THEORY POWERS PRIVILEGE ESCALATION

When an attacker gains a low-privileged shell, they exploit OS design primitives: SUID Binaries execute with the file owner's privileges (often UID 0 root) instead of the caller's; Kernel Exploits corrupt kernel page tables or memory structures (Dirty COW, Dirty Pipe) to flip the caller's process token to UID 0; Cron Jobs running as root without strict path controls can be tricked into executing attacker-controlled scripts.

LEVEL 03 // COMMUNICATION PREREQUISITE

Networking Theory, Addressing & Infrastructure

NETWORK ARCHITECTURE

A computer network is an interconnected group of nodes sharing data over transmission media using standardized protocols. Without networking, cybersecurity would be reduced to physical security. Every modern attack surface — from port scanning to web exploitation — traverses network stacks.

LAN (Local Area Network)

High-speed, geographically restricted network (home, office, campus). Managed by a single organization. Switched Layer 2 Ethernet & 802.11 Wi-Fi.

WAN (Wide Area Network)

Spans broad geographical regions (cities, countries). Interconnects multiple LANs via telecommunication providers, leased fiber, and MPLS/SD-WAN.

The Internet

A global public "network of networks" interconnected by Autonomous Systems (AS) using BGP (Border Gateway Protocol) and the TCP/IP suite.

numbers NETWORK ADDRESSING TIERS: PHYSICAL VS LOGICAL VS PORT RFC 1918 & IEEE 802
1. MAC Address (Layer 2)
48 bits (6 bytes): 00:1A:2B:3C:4D:5E

Burned into network interface hardware. First 24 bits = OUI (vendor). Last 24 bits = unique device identifier. Operates only on local subnet.

2. IPv4 Address (Layer 3)
32 bits (4 octets): 192.168.1.100

Routable logical address across network boundaries. Divided into Network bits and Host bits via Subnet Mask (/24 = 255.255.255.0).

3. Port Number (Layer 4)
16 bits (0 – 65,535): :80, :443, :22

Identifies which specific process/service on the host should receive the incoming packet. 0-1023: Well-known; 1024-49151: Registered; 49152+: Ephemeral.

RFC 1918 Private IP Ranges (Non-Routable on Public Internet)
Class A: 10.0.0.0/8 (16.7M hosts)
Class B: 172.16.0.0/12 (1M hosts)
Class C: 192.168.0.0/16 (65K hosts)

Special addresses: 127.0.0.1 (Loopback/localhost), 169.254.0.0/16 (APIPA link-local auto-assigned).

Core Network Protocols Breakdown

ARP (Address Resolution Protocol)

Maps IP addresses (Layer 3) to MAC addresses (Layer 2) on local Ethernet subnets. Vulnerable to ARP poisoning/spoofing.

ICMP (Internet Control Message Protocol)

Diagnostics and error reporting (ping, traceroute). Packets report TTL Exceeded or Host Unreachable.

DNS (Domain Name System) — Port 53

Translates human domain names into machine IPs. Record types: A (IPv4), AAAA (IPv6), CNAME (alias), MX (mail), TXT (SPF/DKIM).

DHCP (Dynamic Host Configuration) — Port 67/68

Automatically issues IP, subnet mask, default gateway, and DNS servers via DORA (Discover, Offer, Request, ACK).

TCP vs UDP (Transport Layer)

TCP ensures reliable in-order byte delivery with 3-way handshake. UDP provides fast, low-overhead, stateless transmission.

SSH (Secure Shell) — Port 22

Encrypted remote administration replacing Telnet. Uses asymmetric key exchange (ECDHE) and symmetric AES session encryption.

LEVEL 07 // APPLICATION LAYER

Web Fundamentals & HTTP Request / Response Anatomy

HTTP/1.1 & HTTP/2

The World Wide Web is an application-layer information system operating on top of the physical Internet. Web applications operate on a strict Request-Response model using HTTP (Hypertext Transfer Protocol). Every web vulnerability (SQLi, XSS, CSRF, IDOR) is ultimately manifested in manipulated HTTP parameters, headers, or responses.

LEVEL 08 // DATA PERSISTENCE

Database Theory & SQL Query Architecture

RDBMS & SQLi FOUNDATION

A database is an organized collection of structured data stored electronically in a computer system. Before attempting to exploit or defend against SQL Injection (SQLi), you must understand the grammar, schema architecture, and parser logic of relational databases (RDBMS).

Relational Schema Building Blocks
• Tables: Named relations containing columns (attributes) and rows (records).
• Primary Key (PK): Unique column identifier for each row (e.g., `user_id = 42`).
• Foreign Key (FK): Column in one table referencing the Primary Key of another.
• Relationships: One-to-One, One-to-Many (Users → Orders), Many-to-Many.
bug_report HOW UNESCAPED STRING CONCATENATION BREAKS SQL SYNTAX
1. Developer writes dynamic string query in application code:
query = "SELECT * FROM users WHERE username = '" + userInput + "' AND password = '" + pass + "'";
2. Attacker provides input designed to close string literal and alter boolean logic:
admin' OR '1'='1' --
3. SQL parser interprets the injected quotes as SQL syntax rather than literal data:
SELECT * FROM users WHERE username = 'admin' OR '1'='1' --' AND password = '...';

The database evaluates '1'='1' as TRUE, and the -- comment sequence discards the password check entirely.

verified_user THE DEFENSIVE CURE: PREPARED STATEMENTS (PARAMETERIZATION)

In parameterized queries, the SQL query structure is compiled by the database engine first with placeholders (? or :username). User input is sent in a separate protocol phase and treated strictly as literal string values — never as executable SQL tokens.

LEVEL 09 // MATHEMATICAL SECURITY

Cryptography Theory: Ciphers, Hashes & PKI

CONFIDENTIALITY & INTEGRITY

Cryptography is the science of securing communication against adversaries using mathematical primitives. It provides three indispensable security guarantees: Confidentiality (encryption), Integrity (hashing & MACs), and Authenticity / Non-Repudiation (digital signatures & PKI).

visibility ESSENTIAL DISTINCTION: ENCRYPTION VS ENCODING VS HASHING FREQUENTLY CONFUSED CONCEPTS
ENCRYPTION
• Two-way (Reversible with Secret Key)

Transforms plaintext into ciphertext using a cryptographic algorithm and secret key. Confidentiality is preserved even if the ciphertext is intercepted.

Examples: AES-256-GCM, RSA-4096, ChaCha20.
ENCODING
• Two-way (Reversible by ANYONE, NO Key)

Transforms data into a different format for safe transmission across binary-incompatible systems. Provides ZERO security or confidentiality.

Examples: Base64, URL Encoding (%20), Hexadecimal, ASCII.
HASHING
• One-way (Mathematically Irreversible)

Maps arbitrary-length input to a fixed-size digest. Impossible to invert. Changing 1 bit completely scrambles the output digest (Avalanche Effect).

Examples: SHA-256, SHA-512, bcrypt, Argon2.
key Symmetric Cryptography (Shared Secret)

The exact same secret key is used for both encryption and decryption. Extremely fast and computationally lightweight. Used for bulk data transmission (disk encryption, TLS payload sessions).

• AES (Advanced Encryption Standard): 128, 192, or 256-bit block cipher. Modes: GCM (authenticated), CBC.
• ChaCha20-Poly1305: Stream cipher optimized for devices without hardware AES instructions.
vpn_key Asymmetric Cryptography (Public / Private Pair)

Uses mathematically linked key pairs: a Public Key (freely shared to encrypt or verify signatures) and a Private Key (kept secret to decrypt or create signatures). Solves the key exchange problem.

• RSA: Based on the prime factorization hardness problem (2048 to 4096-bit).
• ECC (Elliptic Curve Cryptography): Curve25519, ECDSA. Much smaller keys (256-bit) with equivalent security.
LEVEL 10 // ACCESS CONTROL

Authentication vs Authorization & Token Architecture

IDENTITY & TOKENS
badge Authentication (AuthN)
"Who are you?"

Validating the claimed identity of a user or system. Verified via Factors: Something you know (password), something you have (TOTP token, smartcard), something you are (biometrics).

gavel Authorization (AuthZ)
"What are you allowed to do?"

Validating whether an authenticated identity has permission to perform an action or read a specific object. Enforced via RBAC (roles) or ABAC (attributes).

token JSON WEB TOKEN (JWT) ARCHITECTURE RFC 7519

A stateless, self-contained compact token format divided into three Base64URL-encoded parts separated by periods: Header.Payload.Signature

1. Header

Algorithm & token type ({ "alg": "HS256", "typ": "JWT" }).

2. Payload

Claims ({ "sub": "104", "name": "Mihraj", "role": "user" }).

3. Signature

HMACSHA256(Header + Payload, Secret). Verifies integrity.

Security Vulnerability Note: If the server accepts "alg": "none", an attacker can modify the payload (e.g. change "role": "admin") and delete the signature, achieving complete privilege escalation.
admin_panel_settings ACCESS CONTROL MODELS
DAC (Discretionary Access Control):

Object owners decide permissions (e.g., standard Linux chmod/chown).

MAC (Mandatory Access Control):

Enforced strictly by central policy/labels (SELinux, Bell-LaPadula).

RBAC (Role-Based Access Control):

Permissions mapped to job roles (Admin, Auditor, User).

ABAC (Attribute-Based Access Control):

Evaluated dynamically based on user role, time, IP, and location.

LEVEL 11 // CANONICAL TERMINOLOGY

Cybersecurity Fundamentals & Threat Model Vocabulary

CIA TRIAD & STANDARDS
change_history THE FOUNDATIONAL CIA TRIAD + AUTHENTICITY SECURITY PILLARS
CONFIDENTIALITY

Ensuring sensitive data is accessed only by authorized entities. Preserved by encryption (AES, TLS), strict access controls, and least privilege.

INTEGRITY

Ensuring information remains authentic, accurate, and uncorrupted by unauthorized modification. Preserved by hashing (SHA-256), HMACs, and digital signatures.

AVAILABILITY

Ensuring authorized users have timely and dependable access to information and systems. Preserved by redundancy, DDoS mitigation, and tested backups.

Vulnerability WEAKNESS
🟢 Simple: "A flaw or weakness in a system."

Technical: A defect in software code, hardware logic, or security configuration that can be leveraged by an adversary to violate the security policy.

Example: Missing input sanitization in an SQL query (CWE-89).
Exploit MECHANISM
🔵 Simple: "The method or code that takes advantage of the flaw."

Technical: A crafted piece of software, payload sequence, or set of commands that takes advantage of a vulnerability to trigger unintended behavior.

Example: A Python script sending crafted packets to trigger RCE.
CVE vs CWE vs CVSS STANDARDS
• CVE: Common Vulnerabilities & Exposures (Unique catalog ID, e.g. CVE-2021-44228).
• CWE: Common Weakness Enumeration (Category of flaw, e.g. CWE-79 XSS).
• CVSS: Common Vulnerability Scoring System (0.0 – 10.0 severity metric).
IOC vs TTP THREAT TELEMETRY
• IOC (Indicators of Compromise): Forensic evidence of attack (SHA256 hashes, malicious C2 IP addresses, suspicious domain names).
• TTP (Tactics, Techniques & Procedures): Adversary behavior patterns documented in the MITRE ATT&CK framework.
LEVEL 12 // DEFENDER PERSPECTIVE

Detection Theory: Logs, SIEM, EDR & Telemetry

BLUE TEAM ARCHITECTURE

Offensive security cannot be separated from detection. Every attacker action generates telemetry: packets cross network switches, system calls cross the kernel boundary, process trees spawn child binaries, and authentication services log outcomes.

SIEM (Security Information & Event Management)

Aggregates, normalizes, and indexes log streams from hundreds of servers, firewalls, and cloud providers. Correlation rules trigger high-priority alerts on multi-stage attack patterns.

EDR (Endpoint Detection & Response)

Lightweight agents installed on host machines monitoring process creation hierarchies (Sysmon/auditd), memory injection, API hooking, and suspicious behavioral anomalies.

IDS / IPS (Intrusion Detection & Prevention)

Deep packet inspection sensors (Suricata, Snort) evaluating network traffic against known exploit signatures and protocol anomalies. An IPS drops malicious packets inline.

visibility HOW ATTACKS LOOK IN DEFENDER TELEMETRY TELEMETRY FOOTPRINTS
Nmap Port Scan:

Generates thousands of half-open TCP SYN packets within seconds from a single IP, causing hundreds of RST responses and triggering firewall scan threshold alerts.

Web Fuzzing (ffuf):

Web server access logs show an unnatural spike of 500+ requests per second resulting in 404 Not Found status codes with identical User-Agents.

Brute Force / Credential Stuffing:

Authentication logs (/var/log/auth.log or Windows Event ID 4625) record continuous failed login attempts against varying usernames.

LEVEL 14 // VIRTUALIZATION & DEVOPS

Cloud Computing & Container Architecture

DOCKER & SHARED RESPONSIBILITY
Cloud Service Models & Shared Responsibility
IaaS (Infrastructure as a Service):

Provider manages physical hardware/datacenter; customer manages OS, runtime, and apps (AWS EC2, Azure VMs).

PaaS (Platform as a Service):

Provider manages hardware, OS, and runtime; customer manages application code and data (AWS Elastic Beanstalk, Heroku).

SaaS (Software as a Service):

Provider manages the entire application stack; customer manages users and access policies (M365, Google Workspace).

Containers vs Virtual Machines: Linux Primitives

Virtual machines virtualize the hardware via a Hypervisor and run a full guest OS. Containers share the host kernel and rely on native Linux kernel isolation primitives:

• Namespaces: Provide isolated views of system resources (pid for processes, net for network interfaces, mnt for filesystem mount points).
• cgroups (Control Groups): Enforce hardware resource limits (CPU quotas, memory caps, block I/O).
• Capabilities: Slices root powers into granular permissions (CAP_NET_BIND_SERVICE). Running with --privileged disables these protections!
LEVEL 15 // ENTERPRISE IDENTITY

Active Directory Theory & Kerberos Protocol Architecture

ENTERPRISE DOMAINS

Active Directory Domain Services (AD DS) is Microsoft's directory service managing identity, authorization, and centralized device management across 90%+ of global enterprises. Understanding Domain Controllers, Forests, Trees, OUs, and authentication protocols is mandatory before attempting AD penetration testing.

vpn_key KERBEROS TICKET-GRANTING PROTOCOL FLOW (PORT 88) TGT & TGS
1. AS-REQ & AS-REP: User sends timestamp encrypted with their password hash. KDC (Authentication Server) validates and returns a TGT (Ticket Granting Ticket) encrypted with the krbtgt account key.
2. TGS-REQ & TGS-REP: User presents TGT to request access to a specific service. The KDC verifies the TGT and issues a TGS (Service Ticket) encrypted with the target service account's password hash.
3. AP-REQ & AP-REP: User presents the TGS to the target application server (e.g. MSSQL or SMB share) to establish an authenticated session.
Offensive Relevance (Kerberoasting): Any authenticated domain user can request a TGS for any service with a Service Principal Name (SPN). Because the ticket is encrypted with the service account's password hash, attackers extract it from memory and crack it offline with Hashcat or John the Ripper.
Key Active Directory Objects
• Domain Controller (DC): Server hosting AD DS and KDC.
• Forest: Ultimate security boundary in Active Directory.
• OU (Organizational Unit): Subdivision for organizing users and applying GPOs.
• GPO (Group Policy Object): Centralized configuration policies.
• NTLM: Legacy challenge-response protocol (vulnerable to relaying).
LEVEL 16 // SIDE-BY-SIDE MASTERY

16 Canonical Cybersecurity Comparisons

REVISION & INTERVIEW CHEATSHEETS

Mastering cybersecurity requires understanding the subtle yet critical distinctions between closely related concepts. Explore 16 comprehensive side-by-side comparisons covering network protocols, security controls, testing methodologies, and threat categories.

01. TCP vs UDP LAYER 4 TRANSPORT
TCP (Connection-Oriented):

3-way handshake, in-order delivery, flow control, retransmission. Slower. Used by HTTP, SSH.

UDP (Connectionless):

No handshake, best-effort delivery, minimal 8-byte header. Faster. Used by DNS, DHCP, VoIP.

Security: TCP requires SYN flood defense; UDP is easily spoofed for amplification DDoS.
02. OSI vs TCP/IP MODELS
OSI (7 Layers):

Theoretical framework separating session and presentation layers for architectural study.

TCP/IP (4 Layers):

Practical internet standard implemented directly in all OS network driver stacks.

Security: OSI maps defense-in-depth; TCP/IP maps socket programming and raw packets.
03. HTTP vs HTTPS WEB PROTOCOLS
HTTP (Port 80):

Cleartext transmission. Subject to passive eavesdropping and MitM tampering.

HTTPS (Port 443):

Encapsulated in TLS 1.3 encryption. Provides confidentiality, integrity, and server identity validation.

Security: HSTS header forces browsers to refuse unencrypted HTTP fallback.
04. Authentication vs Authorization ACCESS
Authentication (AuthN):

"Who are you?" Validates identity using passwords, MFA tokens, or certificates.

Authorization (AuthZ):

"What can you do?" Checks permissions against roles and access policies.

Security: AuthN flaw = credential stuffing; AuthZ flaw = IDOR (Insecure Direct Object Reference).
05. Encryption vs Hashing CRYPTOGRAPHY
Encryption:

Two-way reversible with secret key. Protects confidentiality of data in transit/rest.

Hashing:

One-way mathematical function. Irreversible. Protects integrity and stored passwords.

Security: Never encrypt passwords; always hash them using salted Argon2 or bcrypt.
06. Symmetric vs Asymmetric Encryption CIPHERS
Symmetric (AES):

One shared secret key for encryption & decryption. Extremely fast throughput.

Asymmetric (RSA/ECC):

Public key encrypts; Private key decrypts. Slower; solves key exchange.

Security: TLS uses asymmetric keys for the handshake, then switches to symmetric AES for speed.
07. Encoding vs Encryption DATA FORMAT
Encoding (Base64):

Data format translation without a key. Anyone can reverse it. ZERO security.

Encryption (AES):

Mathematical protection requiring a secret key. Confidentiality guaranteed.

Security: Base64 obfuscation does not provide security against inspection.
08. IDS vs IPS INTRUSION DEFENSE
IDS (Passive Sensor):

Listens out-of-band via SPAN/TAP port. Detects threats and generates alerts.

IPS (Inline Guard):

Sits inline in the network traffic path. Actively blocks and drops malicious packets.

Security: IPS risk = false positives blocking legitimate traffic; IDS risk = lag in containment.
09. Firewall vs WAF FILTERING
Network Firewall (L3/L4):

Filters by source IP, destination IP, and port number. Blind to HTTP payloads.

WAF (L7 Application):

Inspects HTTP headers, cookies, and JSON/POST bodies for SQLi, XSS, and CSRF.

Security: A network firewall allows port 443; only a WAF analyzes what is inside the 443 stream.
10. Vulnerability vs Exploit OFFENSIVE CORE
Vulnerability (Weakness):

The defect or bug in software code, configuration, or human procedure.

Exploit (Attack Tool):

The crafted input, script, or binary engineered to trigger the flaw.

Security: A vulnerability exists whether or not a public exploit has been developed.
11. CVE vs CWE vs CVSS VULN METRICS
CVE: Specific instance ID (CVE-2021-44228).
CWE: Flaw category type (CWE-89 SQLi).
CVSS: Numerical severity (0.0 to 10.0).
Security: CVSS scores above 9.0 are classified as Critical requiring rapid patching.
12. Virus vs Worm vs Trojan MALWARE
Virus: Attaches to host file; needs human execution.
Worm: Self-replicating across networks without human action.
Trojan: Disguised as legitimate software to deceive user.
Security: WannaCry was a worm combining an exploit (EternalBlue) with ransomware.
13. Process vs Thread OS CONCURRENCY
Process:

Independent address space, private file descriptors. Heavyweight context switch.

Thread:

Shares process heap and code; has private stack. Lightweight execution unit.

Security: Thread concurrency bugs cause race conditions and Time-of-Check Time-of-Use (TOCTOU) flaws.
14. TCP Scan vs UDP Scan PORT SCANNING
TCP SYN Scan (-sS):

Fast and deterministic. SYN-ACK = Open; RST = Closed. Minimal timeout latency.

UDP Scan (-sU):

Slow. No response could mean open or filtered. Relies on ICMP Port Unreachable.

Security: Operating systems rate-limit ICMP responses, making full 65,535 UDP scans take hours.
15. Passive vs Active Recon INTELLIGENCE
Passive Recon:

Zero packets sent to target. Uses OSINT, WHOIS, Certificate Transparency, Google Dorks.

Active Recon:

Direct interaction with target assets via Nmap, ffuf, Nikto. Generates log telemetry.

Security: Passive recon is invisible to target defenders; active recon triggers IDS/SIEM alerts.
16. Black vs White vs Grey Box Testing METHODOLOGY
Black Box: Zero prior knowledge. Simulates external attacker.
Grey Box: Partial user knowledge (e.g. low-priv credentials).
White Box: Full source code, architecture diagrams & root access.
Security: White box provides the most comprehensive vulnerability coverage; black box tests perimeter posture.

Academic & University Revision Quick Reference

EXAM & INTERVIEW REVIEW
10 Key Facts to Remember
  • A process owns virtual memory; threads inside it share memory.
  • MAC addresses operate on Layer 2; IP addresses operate on Layer 3.
  • TCP uses a 3-way handshake (SYN, SYN-ACK, ACK); UDP is connectionless.
  • DNS resolves names to IPs; ARP resolves IPs to MAC addresses.
  • Base64 is encoding (reversible, no key); AES is encryption (needs key).
  • Hashing is one-way and cannot be decrypted.
  • Same-Origin Policy restricts scripts across different origin domains.
  • Prepared statements prevent SQLi by compiling query structure first.
  • SUID binaries execute with file owner privileges rather than the caller.
  • Zero Trust principle: "Never trust, always verify."
Real-World Enterprise Scenario

Scenario: A user clicks a malicious email link while connected to an enterprise network.
Architectural Controls:

  • DNS Firewall blocks domain resolution using Threat Intelligence feeds.
  • Network Segmentation prevents the infected host from reaching the database VLAN.
  • Endpoint EDR detects abnormal child process spawning from Word/Outlook.
  • Least Privilege ensures the user does not possess local administrative rights.
